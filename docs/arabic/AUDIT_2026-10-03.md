# Arabic release audit — 3 October 2026

Hashem requested an audit, repairs and a merge to main so both founders can test Arabic. The reviewed source is Elias's `codex/complete-arabic-support` at `4b104f5`, incorporating main `7cd509e` and both earlier Arabic histories. The audit branch is `codex/audit-arabic-release`. This record supplements the implementation evidence in [EXECUTION.md](EXECUTION.md).

## Findings and repairs

1. **Language selection was missing on public, login and platform surfaces.** Cookie-seeded Arabic tests passed, but a new visitor could not discover Arabic there. Added the existing language controls to the public menu, sign-in header and platform header. A new browser journey chooses Arabic without a seeded cookie, reloads, visits sign-in and the platform, switches back, and checks 360px overflow. The sign-in control fits its existing top row; no screenshot references or tolerances were changed.
2. **The frontend rollout flag did not fully disable Arabic.** Binding an account with saved Arabic, or receiving a storage event, could select Arabic with the language switch hidden. The provider now respects the flag at initialization, account binding, storage synchronization and save retry. A disabled rollout leaves saved browser/account choices intact. Both English and Arabic initial values are covered by a regression test that failed before the repair.
3. **The deployment would delete an existing production index.** The guarded production dry run identified `domainRecords.by_organization_branch_type_created`, absent from the branch schema. Declared its existing four fields (`organizationId`, `branchId`, `entityType`, `createdAt`) to preserve it. The repeated dry run contains no index removals.
4. Corrected the server locale resolver's mock-mode environment name to the repository's `NEXT_PUBLIC_DATA_MODE`.

## Acceptance limits and rollback

This release makes Arabic available for the founders' requested testing. Automated evidence does not certify every translation or every provider-controlled screen. Real Clerk account switching, cross-host authenticated persistence, provider verification/CAPTCHA language, assistive technology and founder wording review still need interactive acceptance. The 14 credential-dependent staging tests were not exercised in this audit.

Existing WhatsApp delivery gates remain: Meta approval of the current templates and inbound opt-out support. This release does not enable a messaging provider or send test messages. Communication language remains separate from the viewer's UI language. Original user content and immutable history are not translated in place.

Roll out the additive backend before the frontend. Set the public Vercel production build flag `NEXT_PUBLIC_RIVET_ARABIC=1`. To hide Arabic again, remove/disable that flag and rebuild the frontend; preserve saved choices, additive fields and frozen documents. Do not roll back by deleting data or indexes. Consult `CURRENT_STATE.md` and the release runbook for actual deployment evidence.
